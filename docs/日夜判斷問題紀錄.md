# 日夜判斷問題紀錄

最後更新：2026-10-08

## 現況

資料庫三個日夜欄位已統一為 **1＝夜間、0＝白天**，預設值都是 0；程式讀取時一律「= 1 才算夜間」。

| 欄位 | 誰決定 | 用在哪 |
|---|---|---|
| `story.is_night_mode` | GenerateGameStory：前端傳的 `is_night_mode`（1 以外都算白天）<br>GenerateByText：AI 從使用者那句話判斷 | 「午夜台灣」勳章、行事曆預設出發時間（夜 19:00／日 10:00）、AI 撰寫劇情、各劇本 API 回傳 |
| `story_node.is_night_only` | 建立劇本時直接複製劇本的日夜 | 地圖 API 回傳給前端（只有顯示） |
| `postcard.is_night` | 前端呼叫 `GenerateAi` 時傳的 `is_night_edition` | 明信片 API 的 `IsNightEdition`、旅程回顧的 `is_night_edition`（只有顯示） |
| `task` | 沒有日夜欄位 | 後端選題型不看日夜，只有 AI 寫題目時知道是夜間劇本 |

## 問題與矛盾

### 1. 明信片的日夜不看劇本

- **現象**：`postcard.is_night` 完全由前端傳的 `is_night_edition` 決定（`Services/Postcard/PostcardCatalogService.cs` 的 `GenerateAiPostcardAsync`），後端不比對劇本或節點。
- **結果**：白天劇本可以拿到夜間明信片，反之亦然。
- **目前資料**：明信片 33（劇本 54、節點 235）是夜間，但劇本和節點都是白天。
- **待決定**：明信片日夜要「跟著劇本」，還是「前端自由決定」（例如依拍照時間）？

### 2. 夜間版明信片只是一個標記

- **現象**：呼叫 AI 生成明信片時只送照片、景點名稱、提示詞，`is_night_edition` 沒送過去。
- **結果**：夜間版和白天版的圖片在生成上沒有任何差別，只差資料庫的一個欄位。
- **待決定**：夜間版要不要有不同的圖片風格？要的話需要 AI 服務支援。

### 3. 「僅限夜間解鎖」沒有真的限制

- **現象**：`story_node.is_night_only` 欄位說明是「是否僅限夜間解鎖」，但後端解鎖只看關卡進度，不看現在時間（`dao/Map/MapDao.cs` 只是把值回傳）。
- **結果**：白天也能照常玩夜間劇本的每一站。
- **待決定**：要不要在後端加時間檢查？還是交給前端提示就好？

### 4. 節點日夜和劇本永遠相同，欄位重複

- **現象**：兩個建立劇本的流程都把整本劇本的日夜複製到每一站（`Services/Story/StoryService.cs` 的 `GenerateStoriesAsync`、`dao/Story/StoryDao.cs` 的 `SaveFullAiGeneratedStory`）。
- **結果**：沒有「某一站單獨限夜間」的設計，`is_night_only` 等於 `story.is_night_mode` 的複本；兩者被手動改到不一樣時就會矛盾（劇本 1 曾經發生過，已修正）。
- **待決定**：要做「單站限夜間」嗎？不做的話可以考慮改成直接讀劇本的日夜。

### 5. 遊你說了算（GenerateByText）的日夜交給 AI

- **現象**：後端只把使用者那句話送給 AI，日夜由 AI 回傳的 `is_night_mode` 決定，後端不再確認。
- **結果**：使用者沒有明講晚上，大概就會是白天；AI 判斷錯也不會被發現。
- **待決定**：要不要讓前端另外帶日夜選項，或用 AI 回傳的 `parsed_intent.is_night` 做比對？

### 6. 和 AI 服務的編碼不同

- **現象**：AI 服務規定 1＝夜間、2＝白天，資料庫是 1＝夜間、0＝白天。
- **處理方式**：只在送給 AI 時轉換（`Services/Story/StoryService.cs` 的 `GenerateStoriesAsync`，`is_night_mode = isNightMode == 1 ? 1 : 2`）。之後新增呼叫 AI 的地方要記得轉，不能直接把資料庫的值送出去。

## 其他
